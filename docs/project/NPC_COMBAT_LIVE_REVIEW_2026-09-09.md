`src/org/dementhium/model/combat/CombatMovement.java:104` converts the chosen destination into walking-queue coordinates using the nearest footprint tile's eight-tile sector. The queue uses the NPC origin's sector. When the large body's nearest tile crosses a sector boundary, these bases differ by eight tiles. Recalculating each tick can repeatedly move the NPC in the wrong direction.

An isolated probe ran the actual movement and walking-queue implementation against stationary targets at 225 offsets per NPC on zero-clipping terrain. Each approach had up to 30 movement steps:

| NPC | Current approach failures | Build-only coordinate experiment |
| --- | ---: | ---: |
| Graardor, size 4 | 85 / 225 | 0 / 225 |
| Zilyana, size 2 | 96 / 225 | 0 / 225 |
| Rex, size 3, newer encounter path | 9 / 225, all initially overlapping | Same 9 / 225 |
| Ordinary NPC ID 1, size 1 control | 0 / 225 | 0 / 225 |

Example: Graardor starts at (3215,3215), target at (3208,3220). He eventually alternates (3206,3212) and (3207,3213), without reaching contact. Nothing blocks either actor. Changing only the two coordinate bases in an isolated copy eliminates all 450 Graardor/Zilyana failures. The candidate is an experiment, not a staged or fully validated fix.

This coordinate defect predates today's changes: those lines are unchanged against the repository baseline. Today's God Wars controllers still inherit it and now require genuine primary-target contact for several attacks. It can therefore account for interrupted pursuit and attacks that never start. Other large NPCs using this path are exposed too; the probe does not establish live failure rates.

### 2. Confirmed regression: Nex's movement action loses its interaction

`Nex.java:1322` now creates a fresh `NexCombatAction` for each attack. The executor asks the persistent prototype for `getCombatType()` before constructing the attack session. However, `Nex.java:1555` still derives its chase decision from that prototype's `interaction`.

Only the new session receives an interaction. The prototype stays null and falls back to MAGIC, or RANGE in shadow. Its former path-dependent melee pursuit branch no longer runs in normal executor selection. The probe reproduces a null prototype and MAGIC movement at eight tiles; a target-initialized session reaches the existing melee-choice branch. This is a direct integration regression from action isolation, not a reason to restore mutable shared pending attacks.

Repair must give Nex explicit target-aware movement/selection state, keep each launched hit independent, and respect phase/special movement locks. The second pass below confirms that her inherited ordinary 12-tile leash also resets combat inside her arena; first-contact handling must be checked against the ordinary aggression issue below.

### 3. Confirmed: new encounter timers can land attacks in their launch tick

`NPCTickTask.java:37` runs combat before `npc.tick()` at line 45. `EncounterNPC.schedule()` uses its current local clock; `EncounterNPC.tick()` immediately increments that clock and runs due tasks. A one-tick attack scheduled during combat is already due later in the same NPC task.

Through the real NPC task, forced KBD melee animates with sequence 80 and removes 196 LP in that same task, while its local clock advances 0 to 1. That violates the attack's nominal one-tick delay. Longer delays scheduled before the clock increment have the corresponding offset. This affects the common controller behind Corp, KQ/Kings/Spinolyps and the advanced bosses (TD/KBD/Chaos/frost). God Wars uses a different world-clock room scheduler and does not share this particular error.

Repair needs a defined launch-tick/due-tick contract. Do not blindly add one to every timer: tasks scheduled from encounter mechanics already run after clock advancement, and death/phase/add schedules have different callers. Preserve exact intended intervals and cancellation ownership at each caller.

### 4. Bandos animation and cadence: partly verified, visual cause still open

The active route is `Bandos -> GodWarsNPC -> GodWarsAction`, not the loose root `combat/` tree or the old `BandosAction` implementation.

The active shockwave still selects animation **7063**, and melee selects **7060**. The real NPC task leaves 7063 in the outgoing animation mask when the shockwave starts. Stationary cadence probes observed:

- Graardor attack starts at ticks 0, 6, 12, 18; positive shockwave impacts at 1, 7, 13.
- Zilyana attack starts at 0, 2, 4, 6, and so on; positive impacts at 1, 3, 5, 7, and so on.

Those match the approved six-/two-tick intervals and one-tick non-projectile impacts. They do not support a general stationary cooldown slowdown. Failed approaches can add pauses before launch; live scheduling latency was not measured.

Presentation did change: the older Graardor action used projectile 1200/end graphic 1218; `GodWarsAction` has neither for the shockwave. The latest custom report explicitly adopted that presentation pending live checks. Their absence is therefore a presentation difference to review, not automatic authorization to restore the old assets or proof that the arm animation is wrong.

Animation interruption also needs a targeted trace. `RangeAction.java:67` can send a victim's defence animation on a later tick; the mask stores only the current tick's sequence, not the lifetime/priority of a sequence still playing in the client. This code alone does not establish the cause of the reported missing stomp. Verify sequence identity, priority/interruption, movement interaction and packet playback in the developer client before declaring the visual problem fixed.

### 5. New movement path has no melee overlap recovery

Rex's nine failed cases all begin with the player inside its 3x3 footprint. `EncounterNPC.follow()` moves its origin toward the player's tile, eventually reaches that same origin, and then requests a zero step forever. Ordinary non-overlapping empty-ground approaches succeed in this probe.

Define encounter-appropriate recovery from overlap and test it. Preserve intended walk-under tactics, Corp's separate stomp mechanics and legitimate rock safespots; do not implement universal teleporting or obstacle bypass. Also test blocked diagonals with a legal direct cardinal step, where the newer path currently only attempts its chosen direction.

## Additional pre-repair review: confirmed failures

### 6. NPC death chooses reward ownership before crediting the lethal hit

`DamageManager.apply()` credits NPC damage after `updateDamageAttributes()` calls `NPC.hit()`. A lethal hit synchronously enters `NPC.sendDead()`, which has already selected its killer and captured the eventual loot owner. The damage ledger is correct afterward, but that does not repair the earlier death callbacks. Player victims already have explicit credit-before-death ordering; NPC victims do not.

Through the actual damage/death/timer path, an ordinary NPC with 30 LP killed in one hit produced **zero loot callbacks** despite the final ledger naming its attacker. With two players dealing 10 and then the remaining 20 LP, the callback paid the earlier 10-LP attacker. Probe subclasses only replace `loot(Mob)` with a recorder: no real drop table or ground-item creation was exercised. God Wars inherits the same death method, so its loot and immediate death-credit consumers also need coverage. EncounterNPC has a separate deferred killer lookup and is not the demonstrated failing route.

Repair death-credit ordering while retaining actual LP loss, overkill clamping, immunity and no double credit. Cover one-hit kills, a lethal hit changing the leading contributor, healing/misses, and relevant immediate kill-progress callbacks. Include connected Barrows/Fight Caves/God Wars cases if this shared contract changes. Against the repository baseline, typed damage used to credit before HP mutation; do not attribute this to documentation or infer an exact introduction date from an uncommitted diff.

### 7. Nex arena cleanup cancels the successful kill's loot callback

Nex's lethal hit schedules wrath for three ticks later. `NPC.sendDead()` then schedules loot with a seven-tick delay. `NexAreaEvent.execute()` notices `isDead()` within its two-tick event cycle and removes Nex. `EntityList.remove()` calls `NPC.destroy()`, advancing her combat generation; the generation guard in `NPC.submitWorldTick()` consequently cancels the waiting loot callback.

The probe delivers the lethal hit and runs the real wrath/death callbacks. Without arena cleanup, the loot recorder fires once. With the actual arena event between death and loot, it fires **zero times**. This is a lifecycle integration defect: retain cancellation of old combat work, but give completed-kill reward delivery explicit ownership and exactly-once completion before disposal. Do not remove generation protection globally.

The same lethal-hit probe also observes Nex at **0 LP, `isDead()==false`, `isAttackable()==true`** during the wrath interval. Audit this as part of the terminal death state: ordinary attacks, healing, phase advancement and repeat lethal hits must not resume the fight or suppress the single intended wrath/reward sequence. Continued attacks or self-healing during that interval were not reproduced by this probe and must not be reported as an observed live symptom.

### 8. Ordinary aggression clears its own approach before movement

The post-combat reset in `NPCTickTask` clears the target and walking queue when neither actor has a last attacker. Generic aggression then reacquires the same player at the end of the task. Before first contact, this can repeat indefinitely. GodWarsNPC and EncounterNPC are exempt; ordinary NPCs and Nex are not.

A real size-one giant spider (ID 60), with unchanged packed definitions and a suitably low-level fixture player four tiles away, acquired the target but stayed at (3216,3216) for eight actual NPC tasks on empty terrain. Running the same executor and walking queue without the intervening reset moved it immediately to (3217,3216). This is separate from the large-body coordinate error. The reset condition exists in the baseline, so it is not established as a new defect from today's changes.

Replace the last-attacker heuristic with legitimate target/lifecycle validation. Preserve aggression eligibility, single-combat rules, freezes, logout/death/plane checks and leash behavior. Verify acquisition through approach to first impact without supplying fake last-attacker state.

### 9. Kree retains an ineligible unlaunched melee choice

`GodWarsNPC.prepareAttack()` caches the selection while approaching. Kree selects melee when nobody eligible attacks him, but that cached choice survives when a player begins attacking. Through actual NPC tasks, the probe observes `hasAttacker()==true` while the prepared attack remains KREE_MELEE; a fresh selection is a tornado. He can keep pursuing contact instead of responding to the approved attacked/unopposed rule.

Revalidate contextual eligibility before launch and on target changes. Preserve the independence of already-launched hits and their captured damage; do not re-roll every pending attack or every unchanged movement tick. Include both directions of Kree's attacked/unopposed transition and K'ril prayer eligibility without expanding into unapproved damage changes.

### 10. Nex's ordinary leash resets combat inside her arena

From Nex's actual spawn (2924,5202), an origin at (2937,5202) with a player still inside the room triggers inherited `NPC.tick()` return-home logic. The real NPC task sets `returningHome`, drops her target and advances combat generation. `setDoesWalk(false)` prevents random wandering but does not disable this leash. Thus fixing her pursuit alone can expose another reset/cancellation problem at legal arena positions.

Use encounter-owned bounds and cleanup for Nex, preserving ordinary NPC leashes elsewhere. Verify room edges, charges/pulls, departure, empty-room reset and subsequent re-engagement. This is now reproduced in headless code; live occurrence/frequency remains unmeasured.

## Expanded combat review: additional repair requirements

The following findings come from current `src`, including the existing local changes. They are independent of historical formula disputes. Priority P1 means major gameplay/reward failure; P2 means a correctness defect that also belongs in the completion gate. Source line references describe the reviewed snapshot. All reproductions use isolated Java processes and ordinary player fixtures; no running server was attached to.

### 11. P1 — An ordinary NPC dying outside its leash can lose loot and respawn

`NPC.tick():181–201` runs return-home logic even while dead. Death schedules generation-owned loot, hide and respawn callbacks; the following out-of-leash tick calls `resetCombatState()` again and invalidates those callbacks. This is a separate failure from lethal-hit credit and Nex's arena removal.

The probe dealt two actual hits to a 30-LP NPC so the killer was already present in the ledger. With death at twelve tiles from home, the loot recorder fired once and the NPC revived. At thirteen tiles, one actual `NPCTickTask` entered returning-home state after death; after eighty world-timer dispatches there were **zero loot callbacks and the NPC was still dead, visible and at zero LP**. The timer harness does not simulate subsequent walking tasks, but cancellation occurs in that first NPC task and the scheduled respawn is already lost.

Expected repair: terminal death must own its completion, including loot and respawn/removal, and must not initiate ordinary leash recovery. Cover the leash boundary, poison/reflection kills, unrespawnable NPCs and a second life. Do not solve this by dropping generation safeguards. New encounter and God Wars controllers override `tick()`; do not claim they share this precise inherited-leash failure.

### 12. P2 — Returning home restores LP but keeps the previous fight's credit and poison

`NPC.resetCombatState():175` clears pending executor work/current levels, while arrival in `NPC.tick():185` restores HP. Neither clears the ordinary NPC's damage ledger or poison stream. `PoisonManager.start():35` captures poison/instance ownership, not the NPC combat generation. Existing encounter/room reset methods explicitly clear these states, so ordinary reset is inconsistent.

The real follow/queue return took fourteen NPC tasks on empty terrain. The NPC recovered to **100/100 LP**, still named the earlier attacker as its damage leader, and remained poisoned. Dispatching the existing poison timer then reduced it to **80 LP**. Repeated restored fights can accumulate obsolete damage credit; this probe establishes retention and renewed damage, not an actual stolen drop.

Expected repair: define one complete ordinary encounter-reset contract for damage ownership, poison, active status/immunity state and percentage-curse ownership as well as numeric levels. Preserve credit during a continuous fight and KQ's intentional two-form fight. Curse reset/cleanup was already a stated foundation limitation; specify it explicitly without guessing new proc/stacking numbers.

### 13. P2 — Ordinary recoil/Deflect loses the reflecting player's damage credit

`MeleeAction.endSession():88–93`, `RangeAction.endSession():93–98` and `NPCSpell.endSpell():72–78` return recoil/Deflect using `miscDamage`, which supplies a null attacker. Several special handlers retain the same pattern. In contrast, `SpecialHits` and the newer boss impact helpers pass the reflecting victim as the source.

A controlled 100-LP incoming melee hit through the actual ordinary `endSession`/damage path consumed ten recoil charges and removed ten NPC LP, but its damage ledger remained empty. This is an attribution error independent of finding 6's ordering: moving credit before death cannot recover a discarded source. A reflection-only ordinary kill can consequently have no reward owner.

Expected repair: preserve the reflector and actual damage through shared reflection delivery, with no reflected-hit loops, duplicate rewards or invented XP. Validate melee, ranged, magic and affected specials against both NPC and player victims. The controlled probe tests delivery, not natural attack selection; the repair requires executor coverage too.

### 14. P2 — Delayed Vengeance can damage a reset NPC life

`Mob.submitVengeance():583–602` schedules an unowned one-tick world callback with raw integer damage. It captures neither NPC generation nor instance revision. Raw `DamageManager.apply` checks current instance admission but cannot identify the earlier life.

The probe queued a thirty-LP Vengeance reply, ran Corp's real `resetEncounter()`, and dispatched the pending callback. Despite the generation change and full reset, Corp went from **20,000 to 19,970 LP**. This invokes the reset API directly; it does not reproduce a live empty-room transition.

Expected repair: reflected delayed hits must capture their participants' lifetime/instance ownership and reject reset/dead/replaced/departed contexts. Keep normal in-flight reflection working exactly once. Add actual reset/departure entry-path coverage and the connected PvP/duel boundary checks if the shared player route changes. This does not establish that every raw-damage caller is defective; inventory the remaining delayed callers before sign-off.

### 15. P2 — Corp core consumes recoil charges without delivering reflection

`EncounterAdd.tick():36` resolves a typed core hit directly through DamageManager, but never dispatches the resulting recoil, Deflect or Vengeance. `Damage.finishEffects` has already debited recoil charges. Corp's stomp (`CorporealBeast.mechanics():30`) and its depleted-stat extra hit (`EncounterAttack:67`) have the same source-visible delivery omission; only the core was dynamically reproduced here.

Two actual core NPC tasks produced **37 LP player damage, three recoil charges consumed, zero core LP lost**, with Vengeance still active afterward. Corp's healing callback still used actual damage. This is not evidence that Vengeance was consumed: it was calculated and left undispatched.

Expected repair: specify reflection eligibility for these damage categories and settle it consistently. If eligible, apply the reflected result once to the correct source; if intentionally exempt, suppress calculation/charge consumption as well. Preserve core healing, poison pinning, protection bypass and approved damage rates. Include stomp and depleted-stat damage in the regression selection rather than fixing only the sampled core path.

### 16. P2 — Bind, Snare and Entangle still freeze immune victims at cast time

This was already held in `COMBAT_MORNING_DECISIONS.md`; it is now a reproduced repair item. The three `castSpell` methods write `freezeTime`/`freezeImmunity` directly (Bind/Snare:27–29; Entangle:33–35), bypassing the shared impact/contact and status-immunity path used by ice spells.

For **all three spells**, a successful cast froze a hit-immune player before its Damage object was resolved. No impact or HP loss was needed. The probe directly calls the spell with real accuracy rolls; it does not exercise rune debit/packet handling or prove every binding interaction.

Expected repair: use successful-contact ownership at valid impact, including successful zero damage, while rejecting splashes, immune targets and cancelled contexts. Preserve the Impling-specific behavior after reviewing its caller. Test expiry/thaw boundaries, queued movement, manual/autocast entry, NPC targets and teleport/logout. Spell duration calibration remains separate from this functional defect.

### 17. P1 — Combat line of sight ignores directional walls, allowing attacks through them

`ProjectilePathFinder.clearPath():71` checks only `SOLID_FLAG=256`. `Region.addClippingForVariableObject():460` writes directional wall flags, including projectile-blocking counterparts, which that ray ignores. The ray also does not test a boundary on a one-tile segment. Calling it in both directions, as `GodWarsAction.clear():132` does, does not correct this. `EncounterNPC.follow` accepts melee contact using that same projectile predicate.

The probe installed a wall with the **production Region wall-clipping writer** at Rex's footprint edge. The ordinary movement predicate rejected crossing it, but `GodWarsAction.clear` returned true. Through three normal `NPCTickTask` calls and the natural initial cooldown, Rex launched and dealt **59 LP through the wall**. This is synthetic terrain using real wall masks; it does not identify a particular exploitable wall in the live King room.

Expected repair: distinguish melee boundary clipping from projectile line of sight, handle directional walls/diagonal corners and nearest footprint edges, and preserve projectile-passable cover where appropriate. Inventory shared ray callers: player/ordinary NPC attacks, God Wars, encounters and Jad/Fight Caves. Validate actual cache terrain and all orientations/planes as well as solid-tile probes. Preserve intentional rock safespots; fixing pursuit must not permit attacking through cover.
